# Upgrading to 0.2.0

In 0.2.0, the `hue_scene` attributes that took JSON strings take objects, and
`kelvin` is removed. Configuration written for 0.1 needs rewriting, including
the configuration that Terraform generated on import. `hue-tf migrate`
rewrites it. The state upgrades by itself at the next plan, without contacting
the bridge.

## What changed

| 0.1 | 0.2.0 |
|---|---|
| `palette = jsonencode({ color = [{ color = { xy = XY }, dimming = { brightness = B } }] })` | `palette = { color = [{ color_xy = XY, brightness = B }] }` |
| `color_temperature = [{ color_temperature = { mirek = M }, dimming = { brightness = B } }]` in the palette | `color_temperature = [{ mirek = M, brightness = B }]` |
| `effects_v2 = [{ action = { effect = E, parameters = P } }]` in the palette | `effects_v2 = [{ effect = E, parameters = P }]` |
| `gradient = jsonencode({ points = [{ color = { xy = XY } }, ...], mode = M })` | `gradient = { points = [XY, ...], mode = M }` |
| `effects_v2 = jsonencode({ action = { effect = E, parameters = P } })` | `effects_v2 = { effect = E, parameters = P }` |
| `dynamics = jsonencode({ duration = D })` | `dynamics = { duration = D }` |
| `kelvin = K` | `mirek = provider::hue::mirek_from_kelvin(K)` |

The new forms follow the API but flatten wrappers that hold one field, as the
action attributes `brightness`, `color_xy` and `mirek` already do. In effect
parameters, `color = { xy = XY }` becomes `color_xy = XY`, and
`color_temperature = { mirek = M }` becomes `mirek = M`. The palette no longer
takes the deprecated `effects` list. The deprecated `effects` of an action
stays a JSON string.

Configuration in the 0.1 form fails at plan, before anything is sent to the
bridge, with errors such as:

```
Inappropriate value for attribute "palette": object required.
Inappropriate value for attribute "actions": element "...": attribute "gradient": object required.
kelvin was removed in 0.2.0. Write mirek = provider::hue::mirek_from_kelvin(2700) instead, ...
```

## Steps

1. Commit or back up the configuration.
2. Update the provider with `terraform init -upgrade`, and get a `hue-tf`
   that has the `migrate` command from the
   [GitHub releases](https://github.com/akr4/terraform-provider-hue/releases).
3. Run `hue-tf migrate` in the root of the configuration. It also reads the
   local modules that the root calls from inside it. To read other
   directories too, name them: `hue-tf migrate . ../other`. It prints the
   changes as a diff and changes no file.
4. Run the command that it prints at the end, such as
   `hue-tf migrate --write`, to rewrite the files.
5. Rewrite by hand what it lists under "Not rewritten", and look at what it
   lists under "Rewritten. Check these".
6. Run `terraform plan`. The rewritten scenes show no changes.

## What migrate rewrites

- The `jsonencode` of `palette`, and of `gradient`, `effects_v2` and `dynamics`
  in actions, including lists made with `for` expressions.
- `kelvin` in actions, including actions in `merge` and in `for` expressions.
  A kelvin outside the range of `provider::hue::mirek_from_kelvin` becomes the
  mirek that 0.1 sent for it, as a number. A kelvin from an expression becomes
  `provider::hue::mirek_from_kelvin(expression)`. The function fails at plan for
  a kelvin outside the API's range of 50 to 1000 mirek, which 0.1 brought into
  the range.
- `kelvin = null`, and `kelvin` next to `mirek`, which configuration generated
  by 0.1 writes. The `mirek` stays.
- A palette without entries, which configuration generated by 0.1 writes for
  every scene, is removed. Terraform then leaves the palette to the bridge, and
  keeps a palette made in the Hue app. Write `palette = {}` to keep it empty.
- Lists without entries are left out, since they are sent empty.

A file that `terraform fmt` leaves as it is stays formatted, and a file with
CRLF line endings keeps them. Comments inside a rewritten value, or on a line
that migrate removes, are not kept, and migrate says so. It replaces each file
in one step, and stops when a file changed after it was read.

## What migrate leaves

migrate reads the `.tf` files in the directories it is given, and in the local
modules that they call from inside them, without other subdirectories. It
rewrites only what is written in each `hue_scene`, and changes no file when one
cannot be parsed. It lists, without rewriting:

- values that come from variables, locals or other expressions,
- JSON in a string, and files in the JSON syntax,
- palettes with entries in the deprecated `effects` list,
- symbolic links. It names the directory that a link points to, and reads the
  file there when that directory is named too.

A local module outside the directories may be shared with configurations that
still use 0.1, so migrate only points at it when it has `hue_scene` resources.
Run it there too when nothing on 0.1 shares the module. Modules from a registry
are not read.

## Terraform before 1.8

`provider::hue::mirek_from_kelvin` needs Terraform 1.8 or later. With an older
Terraform, write the mirek as a number. The error for `kelvin` gives it, as in
`mirek = 370` for `kelvin = 2700`.
